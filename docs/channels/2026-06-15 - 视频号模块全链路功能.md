## 这次更新是干什么的

这篇记录主要跟进微信「视频号(Channels / Finder)」这一整块功能的研究进展。和前面只针对登录、安全验证某个单点不同，这次是把视频号从登录、初始化、开通、浏览、搜索，一直到互动(点赞 / 收藏 / 评论 / 弹幕 / 私信)的完整链路都打通了。

换句话说，这次更新的重点不是某一个 cgi，而是「这一整块能力能不能从头到尾跑通」。现在的研究结论是：视频号这一块已经具备全链路可联调的能力，不再只停留在单接口分析。

## 它最终是为了解决什么事情

这次更新解决的是：

- 视频号这一块，很多外部需求不是只要「能看」，而是要能登录、能开通、能搜索、能互动
- 如果只做出一两个孤立接口，整条链路还是跑不起来，业务上用不了

如果不把全链路打通，常见现象就是：

- 能拿到账号登录态，但视频号进不去(没初始化 / 没开通)
- 能看到内容，但点不了赞、发不了评论、发不了弹幕
- 能拿到分享链接，但解析不出视频信息、查不到详情
- 各个接口散落，没有统一的设备 / 登录上下文承接

## 研究思路

视频号这一整块，公开层面可以按链路顺序拆成几段：

```text
登录(助手扫码)
  -> 初始化 / 资料中心
  -> 开通(未开通时)
  -> 浏览 / 搜索 / 详情
  -> 分享解析
  -> 关注
  -> 互动(点赞 / 收藏 / 评论 / 弹幕 / 私信)
```

下面按这段顺序简单说明每一节都做了什么。

### 登录与初始化

- **视频号助手扫码登录**：走 `3rd-geta8key` 用二维码 url 换带 token 的 fullURL，再调 `scan-qrcode` 拿到 finder 列表，选择后 `finder-handle-auth` 完成确认登录。
- **首页初始化**(`finderinit`)：返回自己的视频号资料，以及是否已开通的标记。
- **功能状态查询**：可以判断视频号功能是否可用 / 是否被封禁。

### 开通视频号

对于还没开通视频号的账号：

- **开通前准备**(`findernewuserprepare`)：返回昵称长度限制、是否已有视频号等前置信息。
- **创建视频号**：把账号真正开通成一个视频号。

### 浏览与查询

- **用户主页 / 用户信息 / 视频列表**(`finderuserpage`)：同一个接口同时返回用户资料和视频列表，支持翻页。
- **视频详情与评论**：拿单个视频的详情和评论。
- **搜索**(`findersearch`)：视频号内容搜索。

### 分享解析

- **分享链接解析**：走 `channels.weixin.qq.com` 的公开 web API 解析分享页，把视频号短码解析成视频基础信息。这里有一个公开结论是请求必须带正确的 `Referer`，否则会返回权限校验失败。
- **分享链接直查详情**：先解析分享链接拿到对象 id，再用已登录账号直接查视频详情。

### 关注与互动

- **关注 / 取消关注**。
- **互动**：这一节覆盖得比较全——
  - 点赞 / 取消点赞
  - 收藏(心形 / 推荐) / 取消收藏
  - 发表 / 回复 / 删除评论
  - 发送 / 查看 / 删除弹幕
  - 私信：建立会话、获取会话列表 / 档案

互动接口定位一条具体视频时，统一支持两种方式：直接传对象 id，或者只传分享链接由服务端先解析再补全。这样互动这一段不用强制要求调用方先拿到 id。

## 现在已经能做到什么

现阶段，视频号这一块已经能够：

- 从助手扫码登录一路打通到互动，形成完整闭环
- 区分「未开通」和「已开通」账号，未开通的可以走开通流程
- 统一用已登录账号的设备 / 登录上下文发请求，不再各接口各拼一份
- 互动接口支持「分享链接」和「对象 id」两种定位方式
- 把原本分散的视频号能力整理成一个可对接的功能模块，而不是一次性调试
